CONTEXT OCaml effect systems Researching
OCaml effect handlers were added in OCaml 5.0 (Dec 2022), alongside the new multicore runtime.
Control mechanism, not type-tracked. Effects are unchecked — there's no effect system in the types. You declare type _ Effect.t += E, call perform E, and install a handler that captures a delimited continuation.
Why they added them: concurrency. Schedulers, lightweight threads and async IO in user-land without callback colouring — this underpins Eio.
Relation to multicore. Domains give parallelism; effects give cooperative concurrency. Direct-style code, no >>=.

ANSWER replying to your question
Koka tracks effects in the type system; OCaml 5 doesn't.
Both have handlers — the difference is whether the compiler knows about effects:
Koka — row-based effect typing: every function's type lists which effects it may perform, e.g. <console,exn>. Pure functions have empty rows.
OCaml 5 — effects are untyped: handlers exist, but the type system won't warn you an effect is unhandled. A typed version was prototyped, then cut to ship.
So OCaml shipped the runtime mechanism; Koka is the research vehicle for the type discipline.

Perceus (Precise Reference Counting with Reuse and Specialization) is Koka's compile-time memory management pass. Combined with evidence passing, it makes algebraic-effect handlers cheap enough for production use — the claim checks out.

CONTEXT Granule language — graded modal types, by Dominic Orchard
Granule (≈2017) is a functional research language built on a linear λ-calculus with graded modal types — it tracks how values are used (how many times, under what resources), not just their type. It's a vehicle for exploring the effect/coeffect design space rather than a production language.
